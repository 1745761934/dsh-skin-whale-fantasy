## 六、风险与注意事项

1. **宿主版本对不上**：社区版最高验证宿主为 `0.2.2-rc.3`，本机 `Info.plist` 读出 `0.13.0`（非官方版本号体系）。装完先跑 `purge-community status` + `selfcheck`，标"未验证"就先 `diagnose` 看锚点漂移，不要直接点应用。
2. **重启是必须的**：补丁只有重启后才被加载，当前进程不热重载这些模块。社区版明说"不自动应用、不自动重启"。
3. **两个 profile 分开装**：`web` 与 `desktop` 各自独立，不能只装一个。
4. **网络范围限制**：社区版 README 声明开源版只认本地靶场 IP（回环 + RFC1918），域名先按系统解析，混有公网地址一律拦。
5. **原版不许倒卖**，二开必须署名 `YuJunZhiXue/dsh-purge`。

## 8.2 踩过的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| pnpm store 版本冲突 | `ERR_PNPM_UNEXPECTED_STORE`：node_modules 指向 store/v11，DSH 内置 pnpm 10.34.5 要用 v10 | 改用 DSH 运行时自带的 **pnpm 11.28.5**（`~/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/pnpm`），它正好匹配 v11 store |
| 上游删库导致解析失败 | `ERR_PNPM_FETCH_404 GET codeload.github.com/YuJunZhiXue/dsh-purge` | 先清掉 package.json 里的旧条目再装 |
| pnpm 把手工插件移走 | 6 个插件被挪到 `node_modules/.ignored/` | 复制到 `profiles/web/local-plugins/`，用 `file:./local-plugins/xxx` 写进 dependencies 锁住 |
| selfcheck 路径误判 | 报 36 条 `missing_file`，但实际补丁已写入 | selfcheck 查 asar 内路径，apply/真实运行走 Helper.app；以文件内 `[dsh-purge]` 标记为准 |
| host-status 返回 unknown_runtime | `entry_layout: unknown` | 不影响实际写入，仅诊断层认不出启动布局 |
